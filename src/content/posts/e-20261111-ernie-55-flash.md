2026 年 11 月 11 日，百度通过飞桨官方代码仓库与 Hugging Face 平台宣布，正式以 Apache 2.0 许可证全面开源其研发的大模型 [文心 5.5 Flash（Ernie 5.5 Flash Preview）](https://github.com/PaddlePaddle/Paddle)。该模型采用总参数 2800 亿（280B）、单 Token 动态激活 140 亿（14B）的超稀疏混合专家（MoE）架构，并提供完整的微调代码、量化工具链与推理部署镜像。

在经过 11 月 5 日基座版本的局部测试后，全量版本的开源标志着百度大模型研发路线从过往以闭源商业接口为主的策略，转向兼顾开源生态分发与云端基础设施服务。

## 商业考量与生态演进背景

在 2026 年中国大模型市场中，开源权重的竞争持续加剧。上半年 DeepSeek-V4 依托低调用成本推动了行业定价调整，7 月月之暗面开源 2.8 万亿总参数的 Kimi K3，阿里巴巴通义千问系列与智谱 GLM 亦保持密集迭代。

在此背景下，百度此前推出的文心 5.0 与 5.1 闭源接口面临开发者对可自部署权重与极致推理成本的诉求。在 2026 年第三季度的行业选型讨论中，[财经媒体与科技社区多次记录](https://www.infoq.cn)了企业客户在千帆大模型平台上评估极高并发场景时，对第三方开源轻量模型在吞吐与成本方面表现的关注。这一市场反馈推动了百度内部加速轻量稀疏模型的工程研发与开源交付。

## 280B 超稀疏混合专家架构

根据百度在 [Hugging Face 发布的模型技术文档](https://huggingface.co/baidu)，文心 5.5 Flash 核心针对工程部署中的显存占用与长文本高并发吞吐进行优化：

- **稀疏路由机制**：模型包含 64 个路由专家与 4 个共享常驻专家。在处理每个 Token 时，系统仅路由激活 4 个最相关的专家网络，将单次前向传播的等效激活参数严格限制在 14B，从而在保留 280B 知识覆盖的同时，显著降低浮点运算量；
- **原生 100 万 Token 上下文**：支持 1M 上下文窗口，结合分块稀疏交叉注意力（Chunked Sparse Attention）与动态键值缓存（KV Cache）剪枝算法，在完整代码仓库检索与长篇技术文档问答中维持稳定的端到端吞吐；
- **消费级硬件兼容**：通过 INT4 和 FP8 混合量化方案，文心 5.5 Flash 的满血运行显存门槛被压缩至两张消费级显卡（如 RTX 4090）或单张企业级数据中心芯片（如 H20），单并发生成速度维持在每秒 100 Token 以上。

## Code Arena: WebDev 基准测试表现

文心 5.5 Flash 在工程代码生成尤其是全栈 Web 开发能力上进行了定向后训练。在模拟真实开发环境的评测基准 **Code Arena: WebDev**（要求模型在无人工干预的多文件项目中，结合真实无头浏览器环境完成现代 Web 应用编写、样式排版与 Playwright 自动化测试调试）中，该模型取得了 1668 分。

## 开源反响与商业化路径调整

文心 5.5 Flash 发布后，开源社区反响迅速。其代码仓库在上线首周即在 GitHub 上获得广泛关注，并迅速被 Cursor、Continue 以及 Roo Code 等主流智能开发插件集成支持。

在商业模式上，百度智能云相应调整了服务布局：在完全开放模型权重的基础上，千帆平台转向提供文心 5.5 Flash 的托管部署、私有化集群调优以及飞桨硬件加速套件增值服务。这一举措使百度在大模型开发者生态中重新建立了基于开源协议的技术影响力，也为中美前沿开源模型的工程竞争增添了重要变数。
